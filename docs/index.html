What dhole digs up

dhole sniffs through your project files and reports every CLI tool it finds — along with whether each one is actually installed.

Deep file scanning

Digs through Makefiles, shell scripts, GitHub Actions, GitLab CI, Dockerfiles, Justfiles, Taskfiles, and docker-compose files. If a CLI tool is referenced, dhole finds it.

Smart word boundaries

node_modules won't false-positive on node. Matches are precise, not greedy.

Version detection

Tries --version, -v, and version subcommands with timeout protection. Reports what you actually have installed.

CI-ready quiet mode

Pass --quiet and dhole returns only an exit code. Drop it into any CI pipeline as a preflight check.

Threaded checks

Pure Rust, no regex crate, no config files. Version checks fan out across threads — projects with dozens of deps finish in milliseconds.

60+ tools recognized

Docker, kubectl, aws, terraform, cargo, npm, python, gh, deno, bun, mvn, gradle, gcc, and many more — out of the box.

Real examples

dhole works right out of the box. Point it at any project directory.

Scan a specific directory:

~

$ dhole ./infrastructure/

CI preflight — fail the build if any dependency is missing:

ci.yml

$ dhole --quiet && echo "All tools present"

All tools present

Verbose output shows which files reference each tool:

~/my-project

$ dhole --verbose
